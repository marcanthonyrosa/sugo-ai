SUGO DEMO KIT — porting reference

This documents the demo kit installed in concept-1a-cobalt-gold.html (the reference implementation): a font-pack switcher (Native + 5 packs) and a hero-art toggle (pot | pixel-chunky | pixel-16bit), persisted across pages via localStorage (sugo-demo-fontpack / sugo-demo-heroart). Every injected block in 1A is delimited by <!-- SUGO-DEMO-KIT START --> … <!-- SUGO-DEMO-KIT END --> (HTML) and /* SUGO-DEMO-KIT START */ … /* SUGO-DEMO-KIT END */ (CSS). Strip those blocks at integration time. The blocks below are the exact payloads; a porting agent may also copy them straight out of 1A between the markers.

Porting model: the kit is three verbatim blocks (HEAD, CSS, PANEL+JS) plus one refactor pass (the target page's display styles must flow through the four tuning vars) plus per-page token mapping for the pixel art (checklist at the bottom).

1 · HEAD block — pre-paint restore + pack font faces

Insert immediately after the page's existing font <link>s. Dedupe: remove any family= / f[]= entries the page already loads (e.g. the butter page already loads cabinet-grotesk and switzer; the moss page already loads Bricolage and IBM Plex Sans).

(The Google URL above includes Space Grotesk and the Fontshare URL includes General Sans for pages that don't already load them — 1A's own copy omits those two because they're native there.)

2 · Refactor pass — display styles must flow through tuning vars

Before the CSS block works, the target page needs four vars in :root and its display rules rewired to consume them. In 1A this meant:

  • Add to :root: --display-tracking (page's native display letter-spacing), --display-lh (native display line-height), --display-weight (native strong display weight, e.g. 700 — Fraunces pages use 600), --display-weight-md (native medium display weight, e.g. 500).
  • h1, h2, h3 rule: line-height: var(--display-lh); letter-spacing: var(--display-tracking);
  • Every display-face rule with the strong weight → font-weight: var(--display-weight). In the Panel Press pages that is: .wordmark · .hero__title · .section-title · .evidence__body h2 · .manifesto__lines li · .foot__statement · .terms__card h2 (the manifesto li and foot__statement also take letter-spacing: var(--display-tracking), and foot__statement takes line-height: var(--display-lh)).
  • Every display-face rule with the medium weight → font-weight: var(--display-weight-md): .hero__strip strong · .bucket h3 · .acc__trigger · .process__own .big · .manifesto__panel h2 · .terms__card dt.
  • The page's mono/outlier face is NEVER switched by the kit.

3 · CSS block — font packs + pixel-art tokens + art states + panel

Insert before </style>. The --px-* token values shown are 1A's navy-flood mapping — REMAP PER PAGE (checklist below). Native state = no data-fontpack attribute; headers stay ≤700 in every pack.

Pages whose token names differ (e.g. no --shadow-stack): map to that page's equivalents; the panel should always use the page's own card/ink/border language. Pages without a --radius-panel/--radius-btn: use their radii tokens.

4 · Hero-art SVGs

Add class="art art--pot" to the existing pot <svg>, then insert these two after it inside .hero__art (or that page's flood container). Both are hand-built rect grids — no external assets. The pot's steam animation is unaffected (it hides with the pot).

5 · Control panel HTML + JS

Insert before </body>, after the page's existing script.

6 · PORTING CHECKLIST (per page)

  1. Keep the page's native fonts as the "Native" state. The kit never changes the mono/outlier face.
  2. Dedupe font links. Remove pack faces the page already loads from the kit's two link tags (e.g. butter page: cabinet-grotesk + switzer already present; moss page: Bricolage + IBM Plex Sans already present; viola pages: switzer already present).
  3. Run the refactor pass (section 2) with that page's native values as the :root defaults (e.g. viola pages: --display-weight: 600; --display-weight-md: 500 for Fraunces; moss page: --display-lh: 1.14; --display-weight-md: 600).
  4. Remap the --px-* tokens to the page's palette and verify art-vs-flood contrast ≥3:1:
    • 1B butter flood (light): coral body works on butter — verify; stem DARK green (~oklch(42% 0.06 150)); 16-bit outline = the page's ink token (classic look).
    • 1C moss flood (dark): coral vs moss ≈ check ~3:1, lighten body a step if short; stem must NOT be green-on-green — use the page's gold or cream; outline = cream/card.
    • 1D indigo flood (dark): coral vs indigo — verify hue clash by eye at demo; stem light basil; outline = card. Flag if coral-on-indigo vibrates.
    • 1E viola-900 flood (dark): coral vs deep viola ≈3.5:1 — verify; stem light basil; outline = card/cream.
    • 1E2 lavender flood (light): coral vs lavender — likely low ΔL, darken body toward pomodoro-ink if needed; stem dark green; outline = the page's navy ink.
  5. Red strategy (stamp-note it): the tomato is the ONLY red-family element on the page (mark-scope license, like Dodonut's bird); pomodoro coral, never pure red; footprint ≤3% of viewport.
  6. Verify: all five packs render headers ≤700 with no clickable-text wrap at 320–1920px; localStorage round-trips across pages; no FOUC (head script BEFORE stylesheets); no horizontal scroll; kit hidden in print; gate 58 (new colors only as tokens); update the page's stamp comment with a SUGO-DEMO-KIT line.
